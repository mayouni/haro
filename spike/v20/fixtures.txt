~~~ The fixtures of rung 20 (Haro v0.20): refinement over the program graph of rung 18, ids from rung 19, for the Ring++ face.
~~~
~~~ Hand-composed BEFORE refine.py existed (the W discipline: fixtures first, code second). A fixture is a Ring program and what happens to it
~~~ when proposals are made against it. Every program is written in its canonical text (the court checks that it is: the diff a refinement
~~~ shows is the printer's, so a program that is not its own canonical form would show layout changes the refinement did not make).
~~~
~~~ THE SECTIONS
~~~   === NN name        a refinement fixture; === TNN name is a TRANSACTION fixture (raw RCP primitives); === LNN, === CNN, === AN as below
~~~   --- program         the Ring text, canonical; ids are 1, 2, 3... in pre-order over its items (rung 19), the numbering the sentences use
~~~   --- context        (optional) the governance tables the gate consults, one block per governance:
~~~                         governance NAME
~~~                         <TAB>actor NAME LEVEL may POINT POINT ...        LEVEL: advisory, delegated, autonomous, emergencyoverride
~~~   --- edited         (optional) the program after a human edited it as text; ids are carried onto it by rung 19's matcher at an EDIT step
~~~   --- do            the steps, one per line, in order:
~~~                         DEFINE REFINE id AS ( ... ) RATIONALE "..." => VERDICT      a refinement sentence and the verdict it must get
~~~                         EDIT                                                         the program becomes `edited`, with carried ids
~~~                       VERDICT is `admitted`, `flagged` (admitted, with cascade warnings) or `rejected STAGE substring-of-why`; an optional
~~~                       ` tx=op,op` after it pins the RCP primitives the sentence lowered to
~~~   --- text          (optional) the canonical text after every step; default: the program's own
~~~   --- run           (optional) `oracle: before | after` -- what the program prints on the oracle and on rnxc, before and after the steps
~~~   --- tx            a transaction fixture: one JSON object per line, each an RCP primitive
~~~ The sentence is the shape `rfn.haro` declares for the declared altitude -- DEFINE REFINE, TARGET, KIND, FROM, TO, AUTHOR, POSTURE, REASON --
~~~ with the optional seats the charter names (AT for the id the proposal was drafted against, CASCADE, REVERTS) and the kinds of the computing
~~~ altitude (param, algo, pipeline).
~~~ THE GATE, in the order stzRefinableCode runs it: structural, constraint, governance, trust, derivation; the first stage that fails ends the
~~~ proposal, and a proposal that fails anywhere changes nothing.

=== 01 the points a program declares
~~~ a tag in a comment is the lift for foreign code (charter 6.1): on the statement's own line, or alone on the line above it. A point's value is the
~~~ literal in the code, so the tag carries no `value=` that could drift from it

=== C02 two spellings are two names
~~~ names are exact (D24): `VAT` names no point, so it is refused in either order and the two sentences commute
--- program
$nVat = 0.20  # <R:PARAM name="vat" min="0" max="0.9">
$nFloor = 0.10  # <R:PARAM name="floor" min="0" max="0.5">
# <R:RULE name="vat-above-floor" expr="vat >= floor" message="vat must not drop below floor">
--- commute
DEFINE REFINE a AS ( TARGET "VAT", KIND param, FROM "0.20", TO "0.30", AUTHOR "m", POSTURE trusted, REASON "r" ) ~ DEFINE REFINE b AS ( TARGET "vat", KIND param, FROM "0.20", TO "0.40", AUTHOR "m", POSTURE trusted, REASON "r" ) => commute

=== A01 a human edit of the text is audited as the refinements it amounts to
~~~ the gate sees a change made as TEXT too: the edit is read back as the refinements of points it makes (ids carried by rung 19), each is run through
~~~ the gate on the old program as the stated author at the stated posture, and the rest of the edit is counted as raw
--- program
$nVat = 0.20  # <R:PARAM name="vat" min="0" max="0.9">
$nFloor = 0.10  # <R:PARAM name="floor" min="0" max="0.5">
$cSort = "quick"  # <R:ALGO name="sort" options="quick|merge|heap" floor="trusted">
? Gross(100)

func Gross(nNet)
	return nNet * (1 + $nVat)
--- edited
$nVat = 0.95  # <R:PARAM name="vat" min="0" max="0.9">
$nFloor = 0.15  # <R:PARAM name="floor" min="0" max="0.5">
$cSort = "heap"  # <R:ALGO name="sort" options="quick|merge|heap" floor="trusted">
? Gross(200)

func Gross(nNet)
	return nNet * (1 + $nVat)
--- audit
as llm
refine vat 0.20 0.95 => rejected constraint
refine floor 0.10 0.15 => admitted
refine sort quick heap => rejected trust
raw 1

=== A02 a text edit of a point's own rule is read back as a refinement of the rule
~~~ widening a bound by hand is the heaviest act a refinement can be, and the gate reads it as one: from an :llm origin it is refused for the origin alone
--- program
$nVat = 0.20  # <R:PARAM name="vat" min="0" max="0.9" risk="1" governed_by="ops">
--- context
governance ops
	actor lead autonomous may vat
	actor boss emergencyoverride may vat
--- edited
$nVat = 0.20  # <R:PARAM name="vat" min="0" max="0.95" risk="1" governed_by="ops">
--- audit
as llm by boss
refine vat.max 0.9 0.95 => rejected trust rule
raw 0

=== A03 a text edit that changes nothing a refinement could change is not read back as one
--- program
$nVat = 0.20  # <R:PARAM name="vat" min="0" max="0.9">
? Gross(100)

func Gross(nNet)
	return nNet * (1 + $nVat)
--- edited
$nVat   =   0.20  # <R:PARAM name="vat" min="0" max="0.9">
? Gross(100)
def Gross(nNet)
	return nNet*(1+$nVat)
--- audit
as trusted
raw 0
