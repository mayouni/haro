# K4 -- does a model write a Python-shaped face better than Ring? Measured 2026-10-20

**The criterion** (CODEGRAPH section 6): "a model does no better writing a Python-shaped face than a Ring-shaped one (then faces are not worth their court, and the graph is justified only by
refinement and the formatter)". **The answer, for the regime measured: it does no better, so K4 is MET.**

## The experiment

Twenty small programs (`tasks.py`), each stated in English, each with a Ring reference solution that passes on the oracle; every reference is also printed through the face and read back
strictly, so every task is sayable in the face. A candidate runs on TWO inputs -- the data its statement shows and data the checker substitutes -- so a program that prints the shown answer
fails (a self-test proves it: gold answers 20/20 in both conditions, hard-coded answers 0/20). One attempt per task. Ring is judged by running it on the oracle (`runtime/win64/ring.exe`, our
own build of Ring 1.27's VM); the face is read by the reader (`face_read.py`) -- **strict**: only the face's own spelling; **lenient**: any text with a meaning -- and the Ring that comes out
is run on the oracle. A third score, **respelled**, takes each answer read leniently, lets the printer write it (the formatter) and reads THAT strictly.

The models are Claude haiku and Claude sonnet, run as sub-agents that read one prompt file and wrote one answer file (two tool calls each, the Read and the Write; told to use nothing else).
Each condition's prompt is a primer of about 200 words and the same twenty tasks.

## The results (`RESULTS.md`, regenerated by `summary.py`)

| condition | model | strict | lenient | respelled |
|---|---|---|---|---|
| Ring, a primer of Ring's facts (R) | haiku, sonnet, two runs each | 20/20 x4 | 20/20 x4 | 20/20 x4 |
| Ring, no primer at all (R0) | haiku / sonnet | 19/20 / 20/20 | 19 / 20 | 19 / 20 |
| the face, round-1 primer (F) | haiku x2 | 1/20, 1/20 | 3/20, 3/20 | 3/20, 3/20 |
| the face, round-1 primer (F) | sonnet x2 | 3/20, 3/20 | 19/20, 19/20 | 19/20, 19/20 |
| the face, primer amended (F2) | haiku x2 / sonnet x2 | 5, 2 / 3, 4 of 20 | 19/20 x4 | 19/20 x4 |
| the face, F2 plus `new` vs `new_without_init` (F3) | haiku / sonnet | 5/20 / 5/20 | 20/20 / 20/20 | 20/20 / 20/20 |

## What it shows

- **Ring is at ceiling, with or without a primer** (haiku 19/20 with none, its one miss a class whose attribute was never initialised -- R24; everything else perfect). A face cannot do better than 100%, so
  it cannot do better. This is the whole of the verdict, and it is also its limit: the tasks do not separate the two where Ring already wins.
- **The face reaches the same ceiling only after its primer was fixed twice**, and what it needed is the cost of a face: a Python reader brings Python's habits and the face refuses them.
  Round 1: haiku wrote `str(x)` for a number in 16 of 20 programs in each run (Python's habit; the face has no `str` but for a handler's message), both models put a class before the statements that use it
  (Python's order; Ring's is the reverse and the primer did not say), and after round 2 every run missed T10 for `new(Name)`, which calls `init` -- an error when there is none. Ring's own
  traps were taught by the same kind of primer and cost the same models nothing.
- **Strict reading is a lint, not a gate.** Sonnet over-spells (`plus(a, b)`, `eq(a, b)`, `gt(a, b)` where the face writes plain operators because both kinds are known), so strict scores sit at
  2-5 of 20 whatever the primer. But the meaning is right (19-20 of 20 lenient) and **every answer that is right in meaning becomes the face's own text when the printer writes it
  (respelled: 20/20)**. The formatter closes the gap; the model needed to know nothing about kinds.

## Limits, stated

Two models, both Claude, run as sub-agents (their tool use was two calls each, which supports that they read and wrote only what they were told, but it is not enforced). Twenty small tasks and
both primers written by the same author, the face's amended twice after seeing failures (the rounds are reported apart; Ring's primer never needed amending). One repetition for R0 and F3.
A ceiling on one side. **Not measured: the regime the memo had in mind, "under its GBNF"** -- a weak model whose decoder is constrained to the face's grammar, where Python priors might help
and a Ring-shaped baseline might not hold at ceiling. The only local chat model on record is SmolLM2 (138 MB), which cannot be expected to pass either shape on these tasks; that regime was
not run, and the grammar it needs was drafted and not pursued (HF-110).

## The decision, taken on the author's delegation (2026-10-20: "answer each question on my behalf and keep going")

1. **K4 is met for capable models: the Python-shaped face is not adopted as a write surface for models.** Rung 6's printer and rung 7's reader stay as built and green: a reading aid, a lint,
   and a respeller (lenient read, then print) -- which is what the measurement says they are good for.
2. **No GBNF for the face** and no further face rungs (lambdas, a runtime for its words): the only consumer of a face grammar is the weak-model regime, where no result is expected today.
3. **The code-graph memo's own rule applies**: the graph is justified by refinement (rung 5) and the formatter (rung 3, and the face's respelling). Neither is touched by this result.
4. Reopen if a stronger local model exists to run under a decoder, or if a task set is found that Ring-shaped fails.
